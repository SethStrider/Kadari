# KADARI — Industry Coverage & Value Accelerators

## Purpose
KADARI must create more value than a basic inventory, asset register, valuation tool or insurance schedule.

The product should become the physical truth layer across industries, while keeping one common Digital Twin and Asset Position model underneath.

## Universal KADARI value stack

Every industry benefits from some combination of:
- physical existence evidence;
- identity evidence;
- condition history;
- ownership/custody/location;
- documents;
- value/replacement value;
- financial reconciliation;
- maintenance/service context;
- insurance readiness;
- audit/inspection readiness;
- transfer/disposal history;
- catalogue/export readiness;
- shareable permissioned record.

## Cross-industry value accelerators

### 1. Smart identity prompts
After first scan, KADARI asks only category-relevant follow-ups, e.g.:
- "Can you find the serial/model plate?"
- "Capture the odometer/hour meter?"
- "Is there a hallmark or certificate?"
- "Add the asset tag?"

### 2. Add Note everywhere
Text or voice note without blocking capture.

### 3. Confidence-driven next best action
The system tells the user what one action will most improve the Digital Twin.

### 4. Repeatable condition views
Use prior evidence to guide future capture and make change comparison easier.

### 5. One-click evidence packs
Generate context-specific packs for:
- insurance;
- audit;
- finance;
- sale;
- valuation;
- estate;
- auction.

### 6. Reconciliation intelligence
Compare physical reality with:
- accounting register;
- insurance schedule;
- finance schedule;
- maintenance system;
- previous KADARI state.

### 7. Catalogue mode
Turn captured assets into exportable sale/disposal catalogues.

### 8. Engagement mode
Professionals manage a defined client job, scope, required evidence, locations, progress and exceptions.

### 9. Unlimited business users
Paid Business accounts should not be seat-constrained. Encourage finance, operations, branch managers and custodians to participate.

### 10. Multi-location / branch hierarchy
One legal entity can contain unlimited or commercially sensible branch/site/location structures under the same company account. Multi-entity groups are treated separately for packaging.

## Product principle
KADARI should continually ask:

> **What can software derive from evidence we already have that creates meaningful customer value without materially increasing COGS?**

That is the value-accelerator standard.
